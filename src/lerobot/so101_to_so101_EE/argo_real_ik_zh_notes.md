# argo_real_ik.py 中文逐行导读

本文按 `argo_real_ik.py` 的源码顺序说明每一段代码的作用。没有把中文注释直接写入
`argo_real_ik.py`，原因是该脚本用于真机控制，直接插入大量逐行注释会显著增加维护成本和误改风险。

## 1. 文件头与整体用途

| 行号 | 作用 |
|---|---|
| 1 | 指定脚本可被类 Unix 环境通过 `python` 解释器直接运行。 |
| 3-15 | Apache 2.0 版权和许可证声明。 |
| 17-24 | 模块 docstring：说明脚本用于在真实 SO101 follower 臂上运行 Argo-Robot/controls 的 URDF IK。 |
| 20 | 强调本脚本使用 `third_party/argo-controls/scripts`，不是 LeRobot 的 `placo` IK 管线。 |
| 21-23 | 说明默认是 dry-run，只读取真机状态、计算 FK/IK 和打印诊断；只有传 `--execute` 才下发电机命令。 |

## 7. 自适应控制参数选择

| 函数 | 作用 |
|---|---|
| `choose_max_joint_step_deg()`，348-380 | 根据当前误差、姿态误差和关节跟踪误差选择每步最大关节变化量；越接近目标越保守。 |
| `choose_replan_interval()`，383-386 | 接近目标时缩短重规划周期，提高微调频率。 |
| `choose_progress_threshold_cm()`，389-397 | 越接近目标，要求的最小进展越小，避免因微小改善被误判为无进展。 |
| `choose_max_stale_steps()`，399-402 | 接近目标时允许更多无明显进展周期，避免过早停止。 |
| `should_pause_replan()`，405-420 | 如果目标附近关节跟踪误差还很大，就暂停重新规划，等电机跟上。 |
| `should_hold_servo_command()`，423-438 | 如果上一条伺服命令还没被电机跟上，就保持上一命令，避免命令越积越远。 |
| `choose_goal_blend_alpha()`，441-448 | 接近目标或跟踪滞后时用更小 alpha 混合新旧 IK 目标，降低跳变。 |

## 14. 运行模式总结

| 模式 | 命令示例 | 行为 |
|---|---|---|
| dry-run | `python argo_real_ik.py` | 读取真机状态，计算目标、候选 IK、预览一步动作，不发电机命令。 |
| 执行 | `python argo_real_ik.py --execute` | 连续伺服 follower，周期性重规划并下发限速关节命令。 |
| 姿态 IK | `python argo_real_ik.py --use-orientation --execute` | 位置和姿态共同参与 IK 误差与收敛判定。 |
| 只看姿态 | `python argo_real_ik.py --orientation-only --execute` | 忽略位置误差，只按姿态误差评价进展和完成。 |
| 固定目标诊断 | `python argo_real_ik.py --execute --fixed-goal-diagnostic-seconds 5` | 不重规划，只持续发送初始 IK 目标，检查电机跟踪误差。 |
| 最终微调诊断 | `python argo_real_ik.py --execute --final-joint-trim-diagnostic` | 测试 IK 解附近的小关节偏置，寻找更贴近目标的实机姿态。 |

## 15. 关键设计意图

- `argo_real_ik.py` 是诊断脚本，不是在线遥操作脚本。
- 默认 dry-run 是为了先验证 FK/IK 预测和目标是否合理，再允许真机执行。
- 多 seed + 多插值方法是为了提高离当前位姿较远目标的 IK 成功率。
- 近目标限速、暂停重规划、保持伺服命令，是为了缓解小舵机跟踪滞后导致的抖动。
- `best_pose_score`、`stale_steps`、`tracking_wait_cycles` 共同决定是否继续尝试、等待电机跟上或停止。
- `final_trim` 是经验补偿，用于处理模型 IK 和真实机械臂之间的小系统偏差。
